# 威胁模型与生产化差距

## 信任模型

**服务端是不可信的转发者。** 它只被允许持有：账号标识、认证令牌、公开密钥材料、密文信封、路由与投递元数据。

它永远不得持有：身份私钥、X3DH 共享密钥 SK、根密钥、链密钥、消息密钥、明文。

这条边界不是靠"服务端承诺不偷看"维持的，而是靠结构维持：客户端从不发送这些材料，服务端 schema 也主动拒绝它们。本仓库用两个测试固化了它：

- 端到端测试读取服务端落盘快照，断言其中不含明文与私钥字段
- 客户端故意提交带 `plaintext` 字段的信封，服务端返回 400

## 攻击面与当前处置

| 威胁 | 处置 | 剩余风险 |
|---|---|---|
| 被动网络监听 | TLS + 端到端加密 | 元数据（谁在何时与谁通信、消息长度）仍暴露 |
| 服务端被入侵/内部人员 | 只存密文与公开材料 | 可推断社交图谱与活跃时段 |
| 预密钥被替换（中间人） | SPK 由身份密钥签名，握手前强制校验 | 依赖用户核对安全码，否则无法发现 |
| OPK 重用 | 服务端认领即删除，客户端消耗后删除私钥 | 服务端若不删则削弱新鲜性，需定期审计 |
| 密文篡改 | AES-GCM 认证，失败即抛错并标记消息失败 | 无 |
| 重放 | 消息密钥一次性；`(ratchet, n)` 唯一 | 明文消息头未加密，序号可被观察（见下） |
| 乱序/丢包 | 跳过密钥缓存，`MAX_SKIP=200` | 超窗口消息进入失败状态而非无限缓存 |
| 身份替换 | AD 绑定双方身份公钥 | 已由测试覆盖 |
| 设备丢失 | 私钥不可导出，注销可清除本地状态 | 首版无远程擦除与密钥备份 |
| 备份泄漏 | 首版不支持密钥备份 | 重装即丢历史会话 |

## 已知差距

1. **消息头未加密**：Signal 规范用 header key（AHEAD）加密棘轮公钥与序号，本实现以明文传输。服务端无法解密正文，但能观察会话节奏与方向切换。生产必须补齐。
2. **自研密码学编排**：`packages/protocol` 的协议编排未经过审计，也未做跨平台互操作测试向量校验。生产应替换为 libsignal / vodozemac。
3. **无 XEdDSA**：这里把 X25519(DH) 与 Ed25519(签名) 拆成两条密钥，语义清晰但与 Signal wire format 不兼容。
4. **数据库未加密**：`expo-sqlite` 明文落库，需换 op-sqlite(SQLCipher)。
5. **无多设备**：一个账号一台设备，`/v1/devices` 预留了多设备结构但未实现设备链表与会话分发。
6. **无群聊**：群聊应走 MLS(RFC 9420)，不要两两通道硬拼。
7. **无恢复机制**：重装无法恢复历史会话。加云备份等于引入新的私钥泄露面，必须配套独立恢复口令与撤销流程。
8. **无证书固定**：移动端应固定服务端证书公钥，并关闭调试代理覆盖。
